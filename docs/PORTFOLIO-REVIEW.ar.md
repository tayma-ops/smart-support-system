# مراجعة جاهزية Smart Support Desk للعرض المهني

> المرحلة النهائية الأحدث: [تقرير جاهزية GitHub](GITHUB-READINESS.ar.md)، بعد إضافة بيانات Atallah Alrashoud وفحص تثبيت مستقل. هذا الملف يحتفظ بتقرير مرحلة التقييم 8.5/10.

تاريخ التحقق: 1 نوفمبر 2026. نُفذت المراجعة على المشروع الحالي داخل `C:\Users\User\smart`، مع إبقاء البيانات والخدمات المحلية. التطبيق متاح على **http://127.0.0.1:8000/**. لم يُنفذ commit أو push أو نشر عام.

## 1. ما الذي كان موجودًا؟

كان المشروع يحتوي نظام تذاكر فعليًا مبنيًا بـDjango وDRF، مع أدوار عميل وموظف ومسؤول، واجهة عربية/إنجليزية، JWT وجلسات، إسناد وأقسام وملاحظات داخلية ومرفقات خاصة وإشعارات وتقارير وSwagger. كان PostgreSQL وRedis وCelery وbeat والنموذج المحلي يعملون بالفعل، وكانت مجموعة PostgreSQL تضم 74 اختبارًا ناجحًا. احتفظت بهذه الميزات وبنظام الاعتماديات الحالي.

## 2. ما الذي تحسّن؟

- أصبحت ميزانيات محاولات المصادقة مشتركة وذات زيادات ذرية عبر Redis، وتشمل دخول الواجهة والإدارة والتسجيل واستعادة كلمة المرور. التسجيل: 5 محاولات POST لكل عنوان في نافذة الساعة؛ المسارات الثلاثة الأخرى: 15 لكل مسار. النجاح يُحتسب أيضًا. التقييد تكميلي وليس حماية من حجب الخدمة.
- أصبح تجديد JWT يفحص تغير كلمة المرور عبر الويب وAPI وإعادة التعيين والإدارة، ويتعامل مع الحساب المحذوف أو غير النشط برفض المصادقة.
- تحسن تنقل الهاتف: منع التركيز على القائمة المغلقة، حصر التنقل بلوحة المفاتيح داخل القائمة المفتوحة، إغلاق Escape وإعادة التركيز، وتصفير الحالة عند تغيير حجم الشاشة.
- حُسنت أحجام نصوص صغيرة على الهاتف، وأُضيف نوع صريح إلى 13 زر إرسال، وأُخفيت 8 عناصر زخرفية عن قارئات الشاشة. عُدلت رسالة توقف AI لتناسب المزوّد المحلي دون الإيحاء بضرورة مفتاح مدفوع، مع ترجمتها العربية.
- أُضيف وضع `bootstrap.py --configure-only` لإنشاء إعداد خاص دون Django أو اتصال بقاعدة بيانات، خصوصًا قبل Docker. اختُبر باستخدام Python دون site packages، مع إثبات عدم استبدال `.env` الموجود.
- أُضيف فحص جاهزية HTTP/قاعدة البيانات لخدمة web في Compose، وفحوص الجودة إلى CI، مع صلاحية قراءة فقط وحدود زمنية للوظائف.
- أُعيدت صياغة README بالإنجليزية، ونُقلت التفاصيل المطولة إلى دليل هندسي مع خطوات إنشاء دور PostgreSQL وقاعدته.

## 5. حالة PostgreSQL وحفظ البيانات

PostgreSQL هو الإعداد الأساسي، وما زال التطبيق الحالي متصلًا به على loopback والمنفذ 55432. لم يُستبدل بـSQLite.

أُخذت نسخة `pg_dump` خاصة قبل العمل، ثم اختُبر إنشاء قاعدة منفصلة فارغة وتطبيق migrations من البداية. اختُبرت استعادة النسخة الاحتياطية في قاعدة اختبار منفصلة أخرى، وطابقت أعداد السجلات الأصلية؛ أُزيلت قاعدتا الاختبار فقط بعد التحقق.

بعد فحوص التكامل طابقت بصمات **جميع حقول السجلات الأصلية** خط الأساس، وطابقت بصمات كلمات المرور أيضًا:

| البيانات الأصلية | العدد المحفوظ |
| --- | --- |
| المستخدمون | 4 |
| الأقسام | 5 |
| التذاكر | 12 |
| الردود | 9 |
| أحداث التذاكر | 12 |
| المرفقات / الإشعارات | 0 / 0 |

بقيت قاعدة SQLite الأصلية والنسخ الاحتياطية الخاصة. سجلات الاختبار التي أنشأتها فحوص التكامل حُذفت بواسطة تلك الفحوص فقط.

## 6. حالة Redis

Redis يعمل على `127.0.0.1:6389` بمصادقة، ويستخدمه وسيط Celery وذاكرة التقييد المشتركة. نجح التكامل الحقيقي معه. نسخة Windows المستخدمة بناء مجتمعي جرى التحقق من بصمته سابقًا؛ ليست ادعاءً بدعم Redis الرسمي لتلك الحزمة. لا تُرفع الحزمة أو إعداداتها الخاصة إلى Git.

## 7. حالة Celery وbeat

العامل المحلي يعمل بوضع `solo` مع `CELERY_TASK_ALWAYS_EAGER=False`. ثبت استقبال وتنفيذ المهام عبر Redis. أظهرت سجلات beat إرسال مهمة الاسترداد كل دقيقة، وأظهرت سجلات العامل نجاح تنفيذها. جدولة تنظيف JWT يوميًا موجودة؛ لم أنتظر دورة 24 ساعة لإثبات توقيتها الفعلي.

تظل حالة المهام معلقة في PostgreSQL عند تعطل النشر، ويستردها beat. يوجد أمر `retry_pending`، ومعامل `--retry-failed` لإعادة الحالات الفاشلة بعد إصلاح إعدادها. البريد ذو ضمان at-least-once وقد يتكرر عند انهيار محدد بعد قبول SMTP. تشغيل Windows الحالي للتطوير؛ لم يُثبت تشغيل عامل Linux بالحاويات هنا.

## 8. حالة الذكاء الاصطناعي

بقي المزوّد المحلي الحقيقي `LocalModelProvider` مع llama.cpp ونموذج Qwen3-0.6B Q4_K_M على `127.0.0.1:8081`. لا يحتاج مفتاح API مدفوعًا. نجح تحليل حقيقي جديد عبر العامل، وبقي مسار المراجعة والتحرير والإرسال الصريح بواسطة الموظف.

العميل لا يرى المسودة أو الملاحظات الداخلية. لا تُرسل المرفقات أو الملاحظات الداخلية للنموذج. النموذج الصغير قد يخطئ، وفحوص رفض طلب كلمات المرور ليست ضمانًا لدقة أو أمان كل مخرجاته. تجارب عربية/إنجليزية فعلية موثقة من التحقق السابق؛ إعادة التحقق الحالية شملت سير العامل الحقيقي. محوّل OpenAI السحابي ما زال مختبرًا بـmocks دون مفتاح أو استدعاء مدفوع.

## 9. حالة Docker

`Dockerfile` و`compose.yaml` و`.dockerignore` جاهزة للمراجعة وتشمل Django/PostgreSQL/Redis/worker/beat وخدمة migrations، مع مستخدم تطبيق دون root وvolumes واستثناءات للأسرار. أُضيف healthcheck للويب ليخدم `docker compose up --wait` وفحوص CI.

**لم يُبنَ أو يُشغّل Docker فعليًا** لأن Docker وبيئة Linux/WSL الجاهزة غير متوفرة. ملف Compose يستهدف التطوير المحلي عبر HTTP؛ عند النشر العام يجب تكييف HTTPS والمضيفين والـhealthcheck مع الوكيل الموثوق. استمر التشغيل الأصلي دون Docker طوال العمل.

## 10. حالة الواجهة والعربية وRTL

راجعت HTML/CSS والقوالب وJavaScript يدويًا، مع نجاح اختبارات العرض لكل الأدوار واللغة العربية. بقيت خصائص `lang/dir` والترجمة وقلب اتجاه التنقل والخصائص المنطقية في CSS وجداول البيانات القابلة للتمرير وتسميات الحقول ورسائل الخطأ والنجاح.

أُصلحت مشكلات التنقل بلوحة المفاتيح وأنواع الأزرار والزخارف وبعض النصوص الصغيرة. **لم تُنفذ مراجعة بصرية فعلية** للهاتف/التابلت/الكمبيوتر: مضيف المتصفح غير متاح، وأوقفت أداة Computer Use الوصول بسبب عدم قدرتها على التحقق من عنوان نافذة المتصفح. لم أحاول تجاوز ذلك. لا تُقدم اختبارات HTML أو تحليل JavaScript بوصفها مراجعة بصرية. أُضيفت خطة التقاط صور حقيقية فقط.

## 11. ملفات GitHub والتنظيم

أُضيفت `LICENSE` برخصة MIT، و`SECURITY.md`، و`CONTRIBUTING.md`، و`pyproject.toml` لقواعد Ruff المحدودة، و`docs/ENGINEERING.md`، وخطة `docs/screenshots/README.md`، وهذا التقرير. حُدثت `.env.example` و`.dockerignore` و`requirements-dev.txt` وCI، دون تغيير نظام الاعتماديات أو حزم التشغيل بلا حاجة.

بقيت `.env` وقواعد البيانات ووسائط الرفع والأدوات والنماذج والسجلات والنسخ الاحتياطية خارج Git. `.env.example` يعرض المتغيرات المدعومة فعلًا مثل `DB_*` و`CELERY_BROKER_URL` بدل إضافة أسماء غير منفذة مثل `DATABASE_URL`.

فُحصت ملفات التسليم الـ129: لا روابط Markdown محلية مكسورة، ولا تطابق مع قيم الأسرار المحلية الفعلية أو كلمات مرور حسابات العرض الأربعة. أُكد تجاهل الملفات الخاصة عبر Git، ووُحدت الملفات النصية إلى UTF-8/LF. هذا فحص لقيم هذا الإعداد، وليس ضمانًا شاملًا لاكتشاف أي سر محتمل في أي تاريخ Git.

حُذفت 11 ملفًا قديمًا غير مستخدم: أدوات/نتائج توطين مؤقتة وأرشيفا تنزيل PostgreSQL/Redis بعد التأكد من تشغيل النسخ المستخرجة وعدم اعتماد أدوات التشغيل على الأرشيفين. حُذفت 15 مجلدًا من caches أو إعداد الاختبار المصطنع، واستُعيد نحو 380.2 MiB من الملفات. حُفظت الأدوات التنفيذية والنموذج وقواعد البيانات والنسخ وبيانات الدخول اللازمة محليًا. جميع مسارات الحذف فُحصت لتبقى داخل المشروع.

CI يعمل عند push وpull_request، مع صلاحية `contents: read` وبيانات اختبار مؤقتة ودون أسرار حسابات حقيقية. يستخدم PostgreSQL/Redis واختبارات العامل، ووظيفة Docker منفصلة. لم يُرفع المشروع ولم يُشغّل CI على GitHub.

## 12. حالة README

README بالكامل بالإنجليزية ويعرض المشكلة والميزات والتقنيات والبنية ودور هندسة Backend: نمذجة وصلاحيات ومعاملات وأقفال ومهام خلفية ومراجعة AI واختبارات. يتضمن التشغيل السريع وPostgreSQL وRedis/Celery وDocker والبيئة والاختبارات والأمان وبنية الملفات والتحسينات وحدود التحقق. التفاصيل المطولة في الدليل الهندسي، والصور مرتبطة بخطة حقيقية دون صور وهمية أو روابط صور مكسورة. لم أختلق اسم المطور أو روابط حساباته.

## 13. ما الذي لم يُختبر فعليًا؟

- بناء/تشغيل Docker وLinux worker: لعدم توفر بيئتهما.
- نجاح GitHub Actions عن بعد: لا رفع ولا push تنفيذًا لتعليماتك.
- العرض البصري والاستجابة الفعلية في المتصفح: أدوات المتصفح غير متاحة؛ أُكملت المراجعة اليدوية والاختبارات بدل التوقف.
- OpenAI السحابي: لا مفتاح حقيقي؛ المحلي يعمل دون الحاجة إليه.
- وصول رسالة إلى صندوق بريد خارجي: لا حساب SMTP خارجي؛ اختُبر بروتوكول SMTP محليًا.
- نشر عام وتحميل مستخدمين حقيقيين وتقييم إحصائي لجودة النموذج واختبار اختراق مستقل.

## 14. الأوامر التي تحتاجها

لا يلزم أمر إضافي لفتح التشغيل الحالي: **http://127.0.0.1:8000/**. بيانات العرض الخاصة في `.local/demo-credentials.txt`؛ لا ترفعها. لإعادة تشغيل هذا الإعداد بعد إعادة تشغيل الجهاز، راجع [دليل الجهاز](LOCAL-SETUP.ar.md).


## 15. التقييم المهني

**8.5/10 للعرض والتقديم على Junior Python / Django Developer.** المشروع يتجاوز CRUD في التحكم بالنطاق والمعاملات والتزامن والتشغيل غير المتزامن والتكامل الحقيقي، مع اختبارات ووثائق واضحة. هذا تقييم لملف Portfolio وليس اعتمادًا لجاهزية تشغيل بيانات عملاء حقيقية.
