# تقرير تسليم Smart Support Desk

> تقرير المرحلة النهائية وأوامر الرفع اليدوية: [جاهزية GitHub](GITHUB-READINESS.ar.md).

> تحديث المراجعة: أصبحت المجموعة **80 اختبارًا ناجحًا على PostgreSQL** بعد إصلاحات المصادقة والإدارة. التقرير الأحدث المطابق لطلب تجهيز Portfolio هو [مراجعة الجاهزية](PORTFOLIO-REVIEW.ar.md). يتضمن حالة الخدمات والأمان والواجهة وDocker وحدود التحقق والتقييم؛ يحتفظ هذا الملف بشرح التسليم الأصلي.

## 1. البنية المعمارية

مشروع Django محلي قابل للتشغيل، بواجهة HTML/CSS/JavaScript وREST API عبر DRF. تعمل الواجهتان فوق خدمات معاملات مشتركة واستعلامات تحصر البيانات حسب المستخدم. PostgreSQL هو الإعداد الافتراضي؛ SQLite خيار تطوير صريح فقط. لا توجد خدمة استضافة مفروضة.

## 2. التطبيقات

`accounts` للحسابات والأدوار، `tickets` للتذاكر والأقسام والردود والمرفقات والإشعارات، `ai_service` للتحليل والمزود، `dashboard` للإحصاءات، و`core` للوظائف المشتركة وأوامر الإدارة. إعدادات التشغيل في `config`.

## 3. النماذج

`User`, `Department`, `Ticket`, `TicketReply`, `Attachment`, `TicketEvent`, `Notification`.

تتضمن العلاقات عميل التذكرة وموظفها وقسمها، عضوية الموظفين في الأقسام، مؤلف الرد، ومالك الإشعار. توجد قيود فريدة للبريد ورقم التذكرة وفهارس لمسارات البحث المهمة. أُنشئت ملفات migrations الفعلية.

## 4. REST API

المصادقة تحت `/api/auth/`، والتذاكر تحت `/api/tickets/` مع إجراءات `reply/`, `status/`, `assign/`, `attachments/`. توجد أيضًا `/api/departments/`, `/api/users/`, `/api/notifications/`, `/api/dashboard/`، وتنزيل خاص للمرفقات. الجدول الكامل للطرق والحقول في README وSwagger على `/api/docs/`. المخطط في `/api/schema/` و`schema.yaml`.

القائمة تدعم البحث برقم التذكرة أو عنوانها، والحالة والأولوية والفئة والقسم والموظف ونطاق التاريخ، والترتيب وتقسيم الصفحات. ترتيب الأولوية يعتمد رتبة فعلية بدل ترتيب الكلمات أبجديًا.

## 5. المصادقة

جلسات Django وCSRF للويب، وJWT للـAPI. التسجيل ينشئ Customer فقط، ولا يستطيع المستخدم ترقية دوره من حقول الطلب. توجد آلية تجديد دورية وblacklist للـrefresh tokens، وتغيير كلمة المرور، واستعادتها بالبريد عبر واجهة الويب.

انتهاء access token بعد 15 دقيقة. تسجيل خروج API يبطل refresh token؛ تظل access tokens القائمة صالحة حتى انتهاء عمرها. تغيير كلمة المرور يبطل استخدامها وفق فحص بصمة كلمة المرور ويمنع تجديد tokens السابقة.

## 6. الصلاحيات

- العميل يرى تذاكره فقط، ويرد عليها ويرفق ملفات ويغلقها.
- الموظف يرى المسند إليه، وما أرسله بنفسه، والتذاكر غير المسندة في أقسامه. يمكنه أخذ تذكرة متاحة وتحديثها والرد وإضافة ملاحظات داخلية.
- التحويل لموظف أو قسم آخر يتطلب `tickets.assign_ticket` أو دور Admin.
- Admin يدير المستخدمين والأدوار والأقسام والصلاحيات عبر Django admin والـAPI، ويدير التذاكر من مساحة العمل.

تغيير معرف URL لا يتجاوز العزل. اختبارات الصلاحيات تشمل القراءة والتعديل والحذف والرد والتعيين. تُعاد مراجعة نطاق الإشعار عند قراءته وعند إرسال بريده بعد تغير الإسناد.

## 7. الذكاء الاصطناعي

تم تنفيذ واجهة مزود قابلة للاستبدال ومحول OpenAI Responses API مع Structured Outputs والتحقق المحلي من القيم والأطوال والمهلة الزمنية. استخدمت إرشادات OpenAI Docs الرسمية لتصميم المحول، والرابط في README.

أُضيف أيضًا مزوّد حقيقي لنموذج محلي عبر llama.cpp، دون مفتاح سحابي. اختُبر Qwen3-0.6B Q4_K_M فعليًا على طلبات إنجليزية وعربية. توجد طبقة ترفض طلبات الأسرار الشائعة، وترفض نتائج غير عربية للطلب العربي بدل عرضها كنجاح.

التحليل يستخرج الفئة والأولوية والمشاعر والملخص والرد المقترح. الاقتراح يظهر للموظف فقط، ويُنقل إلى حقل قابل للتعديل عند اختياره، دون إرسال تلقائي. لا يطغى التحليل المتأخر على triage عدّله الموظف.

عند غياب إعدادات المزوّد تصبح الحالة `disabled` دون نتائج مصطنعة. المزوّد السحابي يحتاج مفتاحًا؛ المحلي يحتاج خادم النموذج المحلي بدل المفتاح. فشل المزود يصبح `failed` ولا يكسر إنشاء التذكرة.

**نجح تحليل حقيقي محليًا وعبر سلسلة PostgreSQL وRedis وCelery**، مع إثبات عدم إرسال رد تلقائي. محوّل OpenAI السحابي اختُبر بعقود وmocks فقط؛ لم يُنفّذ استدعاء سحابي بمفتاح. النموذج المحلي صغير للعرض؛ كشفت التجارب أخطاء تصنيف ولغة واقتراحًا غير آمن، فحُسّنت التعليمات وأُضيفت فحوص الرفض. تبقى دقة المسودات بحاجة إلى مراجعة بشرية، ولم يُجرَ تقييم إحصائي شامل للنموذج.

## 8. مهام Celery

تحليل التذاكر وإشعارات البريد وإعادة توزيع العمل المعلق وتنظيف JWT المنتهية. يتم الإرسال بعد commit، وتبقى الحالة في قاعدة البيانات عند فشل الوصول إلى الوسيط. يستعيد المجدول العمل المعلق والـleases القديمة. يوجد أمر `retry_pending --retry-failed` للاستعادة اليدوية بعد إصلاح الإعدادات.

إرسال البريد من نوع at-least-once؛ قد يتكرر إذا حدث تعطل بين قبول SMTP وتسجيل النجاح. هذا الحد موضح في التوثيق.

نجح إرسال إشعار عبر عامل Celery إلى خادم SMTP اختباري فعلي على الجهاز. لم تُرسل رسائل إلى بريد خارجي. أُضيف `scripts/verify_worker_stack.py` لإعادة الاختبار بقائمة مهام معزولة وسجل SMTP محلي.

## 9. الاختبارات والتحقق

نجحت الاختبارات المحلية التي تغطي الحسابات وJWT وCSRF وعزل البيانات والتذاكر والردود والملاحظات والتعيين والمرفقات والإحصاءات وAI والمهام وقوالب الصفحات. العدد والنتيجة النهائية موجودان في `docs/VERIFICATION.md`.

تشمل الفحوص `check` و`makemigrations --check --dry-run` و`migrate` واختبارات Django وصلاحية OpenAPI و`collectstatic` وفحص توافق الحزم. نجح 74 اختبارًا على PostgreSQL، بما فيها اختبار تنافس موظفين على إسناد التذكرة واختبار منع تكرار تحليل AI بالتزامن. نجح أيضًا اختبار HTTP فعلي بالإنجليزية والعربية، واختبار تكامل PostgreSQL وRedis وCelery والنموذج المحلي وSMTP.

## 10. Docker

ملف Dockerfile يستخدم Python 3.14 وGunicorn ومستخدمًا دون صلاحية root. Compose يتضمن `web`, `postgres`, `redis`, `celery`, `beat`, `migrate` مع volumes وفحوص جاهزية PostgreSQL وRedis وترتيب بدء الخدمات. الخدمة الرئيسية مربوطة بعنوان loopback محليًا، وقاعدة البيانات والوسيط غير مكشوفين على منافذ المضيف.

**Docker غير مثبت على جهاز التنفيذ، ولم تُشغّل الحاويات هنا.** أُضيف CI لبنائها واختبار تكامل حقيقي بعد رفع المستودع، لكن لم يحدث رفع أو تشغيل CI عن بُعد في هذه الجلسة.

تم تجاوز عائق الاختبار المحلي للخدمات بتشغيل PostgreSQL 18.6 وأداة Redis 8.10.3 مجتمعية محمولة لـWindows داخل `.local`، دون تثبيت خدمات نظام. تشغيل Celery بنمط `solo` هنا للتطوير فقط؛ Docker/Linux يظل مسار التشغيل المعتاد للنشر.

## 11. الملفات المنشأة

الكود داخل التطبيقات المذكورة، وملفات الترحيل، وقوالب الواجهة، وملفات static، ومجموعة `tests`، وأدوات `scripts`، و`requirements.in/txt`، و`Dockerfile`، و`compose.yaml`، و`.env.example`، و`.gitignore`، و`.dockerignore`، و`.gitattributes`، و`.editorconfig`، وOpenAPI، وسير عمل GitHub Actions، وREADME وهذا التقرير.

الأسرار المحلية وبيانات العرض وقاعدة SQLite والمرفقات وبيئة Python مستثناة من Git. تم تهيئة مستودع Git محلي. لم يتم إنشاء remote أو تنفيذ push.

## 12. التشغيل

الإعداد المحلي الحالي موجود في مجلد المشروع، مع `.venv` و`.env` وبيانات عرض مسماة `[Demo]`.

التشغيل الحالي يستخدم PostgreSQL فعليًا وRedis وعامل Celery ومجدول beat ونموذجًا محليًا. نُقلت بيانات SQLite إلى PostgreSQL مع التحقق من أعداد السجلات وبصمات كلمات المرور. بقيت قاعدة SQLite ونسخة احتياطية منها داخل المجلد المحلي؛ لم تُفقد حسابات العرض أو تتغير كلمات مرورها.

```powershell
cd C:\Users\User\smart
.\.venv\Scripts\python manage.py runserver
```

ثم افتح `http://127.0.0.1:8000`. بيانات الدخول المولدة محليًا في `.local/demo-credentials.txt`؛ لا تُرفع إلى GitHub. للمستخدم الذي يستنسخ المشروع: اتبع bootstrap في README لتوليد أسراره وحسابات عرضه الخاصة.

يوجد زر **العربية / English** في رأس الصفحة، مع اتجاه RTL وقوالب وحقول ورسوم مترجمة. أُضيف كتالوج gettext من 363 رسالة، ولا يُغيّر نصوص العملاء أو رموز API. فحوص HTTP والعرض البرمجي نجحت باللغتين.

لتشغيل PostgreSQL وRedis وCelery معًا بعد تثبيت Docker:

```text
docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```

## 13. متغيرات البيئة

`SECRET_KEY`, `DJANGO_DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `USE_SQLITE`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `CELERY_BROKER_URL`, `CELERY_TASK_ALWAYS_EAGER`, `CACHE_URL` ومتغيرات AI والبريد وHTTPS. يوجد جدول كامل في README وعينة خالية من الأسرار في `.env.example`.

يجب ضبط `DJANGO_DEBUG=False` وإعدادات HTTPS والأسرار والمضيفين للبيئة المنشورة. `.env` الحالية مخصصة للتطوير فقط.

## 14. ما يحتاج مفتاحًا خارجيًا

AI السحابي يحتاج `AI_API_KEY` و`AI_MODEL` صالحين. النموذج المحلي يعمل دون مفتاح سحابي، وهو المسار المفعّل في هذا الجهاز. الاستخدام اليدوي للتذاكر لا يحتاج AI. التسليم إلى بريد خارجي يحتاج إعداد مزوّد SMTP؛ البروتوكول اختُبر فعليًا بخادم محلي، أما الإعداد الافتراضي للتطوير فيطبع البريد محليًا.

## 16. الحدود والعمل المؤجل

- تشغيل Docker/Compose، ومزوّد AI السحابي، وتسليم SMTP إلى بريد خارجي لم تُختبر هنا. PostgreSQL وRedis وCelery والتحليل الحقيقي المحلي وبروتوكول SMTP المحلي اختُبرت فعليًا.
- الفحص البصري في المتصفح والجوال لم يكتمل: خدمة المتصفح المدمجة غير متاحة، وتوقفت أداة Computer Use لأنها لم تستطع التحقق من عنوان المتصفح على Windows. لم تُختلق screenshots.
- النموذج المحلي صغير، وقد يقترح محتوى غير مناسب رغم تحقق البنية؛ يجب أن يراجع الموظف كل مسودة. فحوص طلب الأسرار لا تمثل ضمانًا شاملًا لأمان مخرجات أي نموذج.
- المرفقات على مستوى التذكرة. لا توجد منظومة فحص برمجيات خبيثة أو تعقيم PDF أو تخزين سحابي خاص بعد.
- إعدادات المزود والبريد والنشر تدار بالبيئة، ولا توجد واجهة عامة لتعديل الأسرار.
- هوية المؤلف وروابطه وترخيص النشر تحتاج اختيار صاحب المشروع؛ لم تُختلق بيانات شخصية.
